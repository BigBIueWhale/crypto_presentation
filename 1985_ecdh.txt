1. THE PROBLEM WITH RSA (THE BLOAT)
-----------------------------------------------------------------------------
RSA relies on factoring massive integers. To remain secure against modern
computing, RSA keys must be massive (3072+ bits).
- RSA Key = A 4-inch steel vault door. Secure, but too heavy for global scale.
- Bitcoin required a key that offered "Vault" security with the weight of a
  credit card to facilitate fast, efficient global propagation.

2. THE MECHANISM (FIRST PRINCIPLES: SCALAR MULTIPLICATION)
-----------------------------------------------------------------------------
ECC relies on the "Discrete Logarithm Problem" on a curve, not factoring.

The Physical Construction of a Bitcoin Key:
Imagine a specific mathematical curve (secp256k1).
There is a fixed starting point on this curve called the Generator (G).

A. The Private Key (The Scalar)
   You pick a random number, let's call it 'k'.
   (In Bitcoin, this is just a 256-bit integer).

B. The Public Key (The Coordinate)
   You perform a geometric operation: You "add" the Generator point (G) to
   itself 'k' times.
   Formula: P = k * G

   - Visual Analogy: You place a billiard ball at point G. You strike it so
     it bounces exactly 'k' times.
   - Result: The ball comes to rest at a specific (x, y) coordinate.
   - THAT COORDINATE IS YOUR PUBLIC KEY.

The Trapdoor:
If I give you the final coordinate (Public Key), it is mathematically
impossible to calculate how many times the ball bounced (Private Key) to get
there.

3. IS A BITCOIN KEY A DIFFIE-HELLMAN KEY?
-----------------------------------------------------------------------------
LITERALLY: YES.
FUNCTIONALLY: USED DIFFERENTLY.

The Mathematical Identity:
A Bitcoin Public Key and an ECDH Public Key are physically the exact same
object: A specific (x, y) point on the secp256k1 curve derived by P = k * G.

If you took your Bitcoin Public Key and I took mine, we could perform the
Diffie-Hellman operation (ECDH) to derive a shared secret code. The math is
identical.

The Application Difference:
1. ECDH (Encryption): Uses the point to *derive* a shared secret to encrypt
   data (e.g., Secure Chat).
2. ECDSA (Bitcoin): Uses the point to *verify* that the person moving funds
   knows the secret 'k' (scalar) without revealing it.

Bitcoin uses the Elliptic Curve geometry to create the keys, but uses the
Digital Signature Algorithm (ECDSA) to authorize transactions.
